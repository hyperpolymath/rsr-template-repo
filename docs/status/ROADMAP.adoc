= rsr-template-repo Roadmap

The journal of the template itself: milestones, blockers and next actions.
A repo minted from the template does not inherit it: `just repo-init`
replaces this file with `build/templates/ROADMAP.adoc.in`.

Phase and maturity are not recorded here. They live in the repo deed,
`rsr-template-repo_chora.deed`, in the `(status …)` and `(maturity …)`
clauses (`just state-phase` prints both).

This file took over the journal half of the retired STATE record
(rsr-template-repo#209), last
updated there on 2026-09-19. STATE also recorded version 0.3.0; the release
version is 0.1.0 (`Justfile`, `CITATION.cff`, tag `v0.1.0`, deed
`(meta :version …)`).

=== 2026-11-16 — contribution-guide and Hypatia consistency repairs

The contribution canary counts all four supported root/.github guide paths
once and rejects duplicates, including mixed-location and same-format pairs.
Regression controls cover the four single guides, no guide and all six pairs.

The RSR oracle now uses the same Hypatia revision as the SARIF scanner and
verdict reporters: `6693f9aed8e4383f78a3d01b600b32663bf7a45c`. The existing
OTP 27 oracle runtime and PinSites compiler guard remain in place. The
workflow-edge gate also inspects Hypatia checkout refs, with controls for
wrong, missing, duplicate and unresolved refs, environment bindings, quoted
keys, repository casing and indentless steps. Shell examples are ignored.

The suppression-policy description is reconciled with the pinned source.
The stale RE008 Dependabot exemption is removed after checking the workflow's
author-id gate, metadata handling and absence of checkout/artifact consumers.
No exemption is added or broadened. These are execution/consistency repairs;
a successful oracle invocation does not establish an RSR compliance tier.

This upstream repair accompanies Secret Types PR #50. Existing template
coverage/debt placeholders remain placeholders for newly minted repositories.

Further review found limitations in the checkout census's hand-written YAML
reader. The follow-up uses verified yq 4.53.3 with a raw mapping-key uniqueness
check before conversion, then structured job/step/input resolution. Estate
Rules already supplies the pinned tool; Squabble and the Proven workflow now
supply the same prerequisite. GitHub workflow-schema validity remains a
separate check. Current-source parser controls and hosted CI are required
before this source repair is considered complete.

PR #418 merged as `0044ad92f9e6ef258b89f3e9b5ee7b748a4db2d2`, with the same
tree as its reviewed head; the parser correction follows in a separate PR.
The existing contribution-canary regression is now wired into Estate Rules.
Shared Sonar maintainability corrections preserve the parser contract and
fixture semantics. Fresh hosted validation must cover the revised source;
the earlier 118-control local passes apply to the pre-Sonar snapshot only.

  window closed on 2026-10-01. The sweep's estate-wide status is not recorded
