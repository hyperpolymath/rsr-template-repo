== Census

3 rows `proven`, 2 `tested-only`, 0 `argued`, 6 `open`: 11 rows in all.

Write the census as a count of rows by status, with the denominator. Never
write a percentage: a count of rows is not a measure of confidence
(README-EXPLAINME §5, PROOF-POLICY §8.4).

== Ledger

One row per obligation, including the ones that are only argued or still
open. Status is one of `proven`, `proven-with-postulates`, `argued`,
`tested-only` or `open`. A `proven` row names the checker, its version and
flags. A row is never stronger than the weakest step it depends on.

The SEAM rows are proved or tested on the ABI seam itself
(`src/interface/Abi/` against `src/interface/ffi/src/main.zig`), which a
minted repository inherits as its own: they hold for as long as that code is
unchanged, and must be rechecked after any edit to it. The ABI and TP rows
are the template's mandatory obligations from `PROOF-NEEDS.adoc`. The files
under `verification/proofs/` prove example statements, not this
repository's. Restate each obligation for this repository's own seam, and
move a row out of `open` only on a receipt below.

Project-specific obligations get their own rows, with their own IDs.
First-party Rust is verified on the code with Creusot (Pearlite contracts)
and Verus (§1.2). A verifier that is not applicable, blocked or not yet run
stays `open`, with the reason in the trust-boundary column.
