= machine-readable Pillar
:toc:

This pillar holds the repository's machine-readable metadata: the records
that let tools and agents read this project's state, boundaries and
obligations without parsing prose.

[IMPORTANT]
====
*Single normative source.* The grammar for the record family in this pillar
is `1-formats/deed/spec/DEED-GRAMMAR-SPEC.adoc` in
https://github.com/hyperpolymath/standards[hyperpolymath/standards]. That
document is the only place the syntax, semantics and typechecking rules are
defined. Every other mention of the format across the estate — including
every README in this tree — is a *pointer* to it, never a restatement.

The format formerly called A2ML is now *DEED* (`.deed`), and no `.a2ml`
file may exist in this repository. The descriptive records are clauses of
the repo deed (`*_chora.deed`) at the repo root, read with
`scripts/deed-field.sh` and written with `scripts/deed-clause.sh`.
====

== Contents

`descriptiles/`:: What this repository *is* and what state it is *in* —
the repo deed's `(meta)`, `(status)`, `(ecosystem)`, `(playbook)`,
`(agentic)` and `(neurosym)` clauses, plus the `(anchor)` clause and the
facet record. See `descriptiles/README.adoc`.

`contractiles/`:: What this repository *ought* to do — the Must, Trust,
Adjust, Intend, Bust and Dust verb sets, each with its declaration, its
Nickel runner and its k9 service-automation component. See
`contractiles/README.adoc`.

`arrival-pack/`:: The entry pack for agents visiting this repository.

`policies/`:: Maintenance axes and related policy records, now the repo
deed's `(policies …)` clauses.

`(rsr-profile)` (repo deed clause):: This repository's declared RSR v2.0 capabilities,
which gate which conformance criteria apply to it. They also widen the root
allowlist: `scripts/check-root-shape.sh` admits every root-level module the
gate table gates on a declared capability.

`template-capability-gates.toml`:: A byte copy of the canon's gate table
(`metadatastician/standards` `.machine_readable/template-capability-gates.toml`),
vendored so `scripts/check-root-shape.sh` can derive the root allowlist without
fetching the canon. Its sha256 must equal the repo deed's `(canon :gates-sha256)`
pin, or the check refuses to run (exit 2): adopting a canon release means bumping
the pin and re-vendoring this file in the same commit. Never edit it here.
